## ✨ ماذا تفعل هذه المهارة؟

بعد التثبيت، يتحول الـ AI الخاص بك إلى **مهندس QA محترف لتطبيقات الموبايل** قادر على:

- 🏗️ **مراجعة المعمارية** — أنماط التصميم، المكتبات، هيكل المجلدات، الترابط بين المكونات
- 🎨 **اختبار UI/UX** — الواجهات، النماذج، الأزرار، الاستجابة، إمكانية الوصول، الوضع الداكن
- 🧠 **الاختبار الوظيفي والمنطقي** — قواعد العمل، انتقالات الحالة، الحسابات، سير المصادقة
- 🔒 **التدقيق الأمني** — تغطية كاملة لـ OWASP Mobile Top 10، لا تنازل عن الأمان
- ⚡ **تحليل الأداء** — تسريب الذاكرة، انتهاكات الـ Main Thread، وقت البدء، استهلاك البطارية
- 📱 **التوافق مع المنصات** — Android وiOS، الصلاحيات، الروابط العميقة، الإشعارات
- 🌐 **مرونة API والشبكة** — معالجة أخطاء كل HTTP Status Code، الوضع غير المتصل، التخزين المؤقت
- 🔄 **إدارة الحالة والبيانات** — Race Conditions، اتساق البيانات، سلامة قاعدة البيانات
- 🛡️ **منع الأخطاء والأعطال** — Null Safety، معالجة الأخطاء العالمية، الحالات الحدية
- ✅ **التسليم النهائي** — ملخص تنفيذي، مصفوفة إثبات الفحص الشامل
- 🔧 **الإصلاح المُهيكل (Phase 11)** — إصلاح الأخطاء المكتشفة بشكل آمن عبر مراجعة دقيقة (Diff) مع فحص أمان تلقائي لكل كود جديد.
- 🏪 **جاهزية النشر التجاري (Phase 12)** — التحقق من سياسات المتاجر (Google و Apple)، حماية بوابات الدفع (Stripe/Paypal)، وتأمين الاشتراكات قبل النشر الفعلي.
- 🔴 **الاختبار الهجومي الآلي (Phase 13)** — الـ AI يثبت ويُشغل أدوات حقيقية (MobSF, apkleaks, nmap) لاختراق التطبيق، مع إلزامية تحديث قواعد الثغرات وإثبات تشغيل الأوامر لمنع الكسل والتأليف.
- 🛡️ **التحقق الاستباقي للإنتاج عبر Sentry (Phase 14)** — إعداد وتفعيل Sentry لتتبع الأخطاء بدليل تفصيلي، والإبلاغ عن الأعطال للقرار النهائي بالإطلاق التجاري.

## 🛡️ نظام مكافحة الكسل المدمج (10 طبقات)

المهارة مصممة لـ **إجبار الفحص الشامل** حتى على الـ AI الذي يميل لتخطي الخطوات.

### ١. استشهادات إثبات العمل (111 كحد أدنى)
كل ملاحظة **يجب** أن تحتوي على مسار الملف الدقيق، رقم السطر، والكود المنسوخ فعلياً.

### ٢. بوابات المراحل الإلزامية (14 بوابة)
كل مرحلة من المراحل الـ 14 تحتوي على Checklist منظمة يجب استكمالها بالأدلة قبل الانتقال للمرحلة التالية.

### ٣. نقاط التوقف الإجبارية
بعد كل مرحلة، يجب على الـ AI إخراج تقرير منظم والانتظار للإقرار قبل المتابعة.

### ٤. مصفوفة التحقق المرجعية
المرحلة النهائية تطلب مصفوفة تثبت فحص كل ملف مع عدد الاستشهادات — أي مرحلة تظهر 0 ملفات يُعلن فيها الفحص ملغياً.

### ٥. إعادة التقييم بعيون جديدة (Fresh-Eyes)
بعد إنهاء الفحص الأولي، الـ AI يقوم بمرور ثاني مستقل بالكامل — أثبتت هذه الطبقة نجاحها في اصطياد الثغرات الحرجة.

### ٦. عقلية المخترق R6 (Hacker Mindset)
بعد كل إصلاح يقوم به، يتأكد الـ AI بوجهة نظر هجومية من أن هذا التعديل لم يُنشئ ثغرات أمنية جديدة أو يتجاوز الحماية.

### ٧. منع الاحتفال المبكر
ممنوع إعلان "جاهزية النشر" بعد مرحلة الإصلاح، لضمان استمرار الـ AI للمراحل الأمنية والاختراق الآلي.

### ٨. 🆕 إلزامية إثبات تنفيذ الأوامر (مرحلة 13)
أي عملية اختراق آلي يجب أن تتم من خلال `run_command` في الـ Terminal — وتأليف المخرجات النصية يُعد غشاً.

### ٩. 🆕 تقييد التخطي اليدوي (مرحلة 13)
لا يمكن التحجج بعدم عمل الأدوات وتخطي المرحلة. مسموح بتخطي أداتين كحد أقصى بسبب مشاكل التثبيت، والباقي إلزامي تشغيله.

### ١٠. 🆕 تحديث قواعد بيانات الثغرات (مرحلة 13)
إلزام الـ AI بتحديث قاعدة بيانات الأدوات الأمنية قبل الفحص والبحث عن أحدث الإصدارات، لضمان فحص التطبيق بناءً على ثغرات العام الحالي وليس بناءً على تدريب الموديل القديم.

## 💬 طريقة الاستخدام مع الـ AI الخاص بك

### فحص كامل
```
راجع مشروعي Flutter باستخدام مهارة mobile-app-tester.
ابدأ من المرحلة 1 واتبع جميع البوابات الإلزامية. لا تتخطَ أي مرحلة.
مشروعي موجود في: [مسار مشروعك]
```

### فحص أمني فقط
```
باستخدام مهارة mobile-app-tester، شغّل المرحلة 4 فقط (التدقيق الأمني)
على مشروع React Native الخاص بي. اتبع جميع فحوصات OWASP Mobile Top 10.
```

### فحص سريع للواجهات
```
شغّل المرحلة 2 (اختبار UI/UX) من مهارة mobile-app-tester على
مجلد الشاشات الخاص بي. افحص جميع الأزرار والنماذج والتصميم المستجيب.
```

### فحص ما قبل الإصدار
```
تطبيقي جاهز للإصدار. شغّل المرحلة 10 (قائمة التسليم النهائية)
من مهارة mobile-app-tester وأعطني توصية الإصدار.
```

## 🔍 مثال على صيغة الاكتشاف

```markdown
### 🔴 [F001]: توكن المصادقة مخزن بدون تشفير

**الموقع:** `lib/services/auth_service.dart:67-71`
**الفئة:** الأمان
**التأثير:** التوكن متاح لأي تطبيق يمتلك صلاحية root — اختطاف كامل للجلسة

**الكود الإشكالي:**
```dart
// السطور 67-71
final prefs = await SharedPreferences.getInstance();
prefs.setString('auth_token', response.token);
prefs.setString('refresh_token', response.refreshToken);
```

**لماذا هذه مشكلة:**
SharedPreferences يخزن البيانات كنص XML عادي على Android. أي تطبيق
يمتلك صلاحية root، أو أي استخراج للنسخ الاحتياطية، يكشف التوكن كاملاً.

**الإصلاح:**
```dart
final storage = FlutterSecureStorage();
await storage.write(key: 'auth_token', value: response.token);
```
**المراجع:** OWASP M9 - تخزين البيانات غير الآمن
```
